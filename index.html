Editor workflows

Where the tools differ

Both cover completion, diagnostics, navigation, references, rename, formatting and semantic highlighting. The differences show up in specific workflows. This comparison uses clice’s tagged 1.0 documentation and clangd’s published docs and release source.

Reproducibility

How the benchmark ran

Workload
183 existing translation units under llvm/lib/Support, selected from the supplied LLVM CMake compilation database at bd49d77ae3c0. The inputs are one LLVM component and its headers. The supplied database covers a much larger build.
Host and binaries
macOS 27.2.1 on arm64, eight logical CPUs and 8 GiB RAM. Official clangd 23.1.0 and clice 1.0.0 macOS binaries. Both received the same CMake commands with staged paths and the macOS 27.2 SDK.
Timing
Wall time from sending the initialized and open-file messages until the language server reported the background index pass ended. Each run used a fresh index cache. OS file caches were left in their normal state. Both servers had a configured background concurrency cap of four, with clice’s startup delay set to zero. clice can reduce concurrency under memory pressure.
Memory
macOS proc_pid_rusage was sampled about every 200 ms. Each row sums the resident set size of the server and all descendants. The mean averages those samples, and the peak is the largest sampled sum. Summed RSS can count shared pages in more than one process and can miss peaks between samples. Raw samples also include physical footprint.
Completion
Translation-unit counts come from the server logs. A progress end event can also occur after skipped work. The results include coverage so a shorter or lower-memory incomplete run cannot be mistaken for an equivalent completed index. The two indexes record different information, and this experiment does not compare coverage at the symbol level.

My take

clice is a worthwhile project with ideas I’d like to see more language servers explore. Process isolation addresses a real reliability problem. Its work on named modules and non-self-contained headers makes a concrete difference for projects that use them.

Those strengths make clice an innovative alternative. Calling it a successor that surpasses clangd across the board would take much broader evidence. The label “next-generation” is too vague to settle which tool fits a given codebase. The workflows you use, the resources your machine has, and the support you can count on matter more.
